Self-host

Runs on your infrastructure

One published container image serves the API and the dashboard on a single port, with the database in a directory you mount and login built in. The dashboard loads no third-party fonts, scripts or analytics.

U0 · Read first

Security notes

  • Login is on from the first start. There's no default password. A new instance prints a one-time setup code to its log, and creating the account needs it, so whoever reaches the instance first can't claim it without also being able to read its logs. Repeated failed sign-ins are slowed down, up to 15 minutes between attempts.
  • One account, no roles. Anyone signed in, and any API token, can scan, sweep subnets and edit remediation records. Tokens can't change the password or manage other tokens.
  • Plain HTTP exposes credentials. CveDeck doesn't serve HTTPS itself. Over HTTP, the password, the session cookie and the SSH credentials you scan with all cross the network readable, so put a TLS reverse proxy in front before exposing it beyond a network you trust.
  • SSH host keys are accepted on first use. There's no host-key verification, so only scan over networks where you accept that risk.
  • Use least privilege. The collector only runs read-only commands, so give it its own unprivileged account on each target, with no sudo.
  • Login can be turned off, with CVEDECK_AUTH=disabled, for instances that already sit behind something that authenticates people, such as Authelia, Authentik or oauth2-proxy. Everything is then open to anyone who can reach the port.
U1 · Demo

Try it with demo data

Demo mode seeds a fictional twelve-host fleet into an empty database and refuses every route that reaches the network: scans, discovery sweeps and connection tests. Leave it off on any instance you actually scan with.

docker run -d --name cvedeck-demo \
  -p 127.0.0.1:3325:8000 \
  -e CVEDECK_DEMO_MODE=true \
  ghcr.io/reprodev/cvedeck:latest

Then open http://localhost:3325. Demo mode needs no login. The threat-intel feeds start empty, so press Refresh intel to download them and see the ranking.

U2 · Install

Scan your own fleet

Docker

Mount a data directory. The database is written there and survives container replacement.

docker run -d --name cvedeck \
  -p 127.0.0.1:3325:8000 \
  -v /srv/cvedeck:/data \
  -e PUID="$(id -u)" -e PGID="$(id -g)" \
  --restart unless-stopped \
  ghcr.io/reprodev/cvedeck:latest

On first start there's no account. Get the one-time setup code from the log:

docker logs cvedeck

Open http://localhost:3325, enter the code, and choose a username and a password of at least 12 characters. To create the account from configuration instead, set CVEDECK_ADMIN_USERNAME and CVEDECK_ADMIN_PASSWORD_FILE.

Then add hosts by address, such as 192.168.1.50, or sweep a subnet such as 192.0.2.0/24 to find hosts to enrol. To build the image from source instead, run docker build -t cvedeck . in a checkout and use cvedeck as the image name.

Docker Compose

From a checkout, copy the example environment file and set the host port, data directory and user IDs. The port defaults to 3325.

cp .env.example .env
docker compose up -d
docker compose logs

The last command shows the one-time setup code for creating the account.

Native Linux (systemd)

For hosts without Docker. Needs Python 3.11 or later, plus Node and npm to build the dashboard. The service binds to 127.0.0.1:8000 only, ready for a TLS reverse proxy, and the installer adds a daily feed-refresh timer.

git clone https://github.com/reprodev/cvedeck
cd cvedeck
sudo ./deploy/install.sh

Find the setup code in the service log:

journalctl -u cvedeck | grep -A4 'no account yet'
U3 · Intel

Keep threat intel fresh

The CISA KEV and FIRST EPSS feeds are refreshed on request, and there is no scheduler in the app yet. Both publish daily, so a daily refresh is enough. The systemd install sets up a daily timer for you. With Docker, add a cron entry on the host.

Crontab entry (crontab -e), refreshing daily at 03:17. It runs inside the container, so it needs no API token. If you set a different PUID/PGID, use those in place of 1000:1000 here and below.

17 3 * * * docker exec --user 1000:1000 cvedeck cvedeck-admin refresh-feeds >/dev/null

Check each feed's age, record count and staleness. The API needs a token, created under Settings in the dashboard:

curl -fsS -H "Authorization: Bearer $CVEDECK_TOKEN" http://localhost:3325/api/feeds

Refreshed intel applies to findings at their host's next scan. How the feeds are used.

U4 · Operating

Running it day to day

  • Network access. Outbound TCP 22 to your Linux targets, and HTTPS to the data sources: OSV.dev, CISA and FIRST, plus NVD if you enable it. For air-gapped networks, point the feed URLs at an internal mirror, for example https://mirror.example.com/.
  • API tokens. Scripts authenticate with tokens created under Settings, sent as Authorization: Bearer. A token is shown once, stored only as a hash, and stops working as soon as you revoke it.
  • Locked out. Reset the password from the host with docker exec -it --user 1000:1000 cvedeck cvedeck-admin reset-password. It also signs out every session.
  • Reverse proxies. Scans run within the request and respond only when the whole batch finishes, so raise your proxy's read timeout to several minutes. Pass the original Host header through. For a proxy in another container, set FORWARDED_ALLOW_IPS to its address or CVEDECK_COOKIE_SECURE=true.
  • SSH keys. For repeat fleet scans, mount a dedicated key read-only and point CVEDECK_DEFAULT_SSH_KEY_PATH and CVEDECK_DEFAULT_SSH_USER at it. The key file is re-read on every scan, so rotating it needs no restart.
  • Backups. With SQLite, everything lives in one file, cvedeck.db, in the data directory. Stop the container and copy it. PostgreSQL is supported through CVEDECK_DB_URL.
  • Upgrades. Pull the new image and recreate the container. The schema migrates forward automatically on start. Back up first, and check /api/health, which reports the running version. Upgrading from 0.6.0 or earlier prints a setup code on the first start, and your fleet and findings are untouched.
